# Построитель фракталов

Учебное графическое приложение на языке C для Linux. Оно строит множества
Мандельброта и Жюлиа, показывает координаты курсора и позволяет увеличивать
интересующую область комплексной плоскости.

Для окна используется GTK 4, а изображение рисуется средствами Cairo.
Математика фрактала реализована вручную в `main.c`.

## Сборка и запуск

Необходимы компилятор C, `make`, `pkg-config` и библиотека GTK 4.

Для Debian и Ubuntu зависимости можно установить так:

```bash
sudo apt install build-essential pkg-config libgtk-4-dev
```

Сборка и запуск:

```bash
cd /home/tka/Documents/sunc/11BGI_AESC/fractal_builder
make
./fractal_builder
```

Или одной командой:

```bash
make run
```

Самопроверка вычислительной части:

```bash
make test
```

## Возможности программы

- построение множества Мандельброта;
- построение множества Жюлиа;
- изменение действительной и мнимой частей константы Жюлиа;
- автоматическая перерисовка после изменения константы;
- отображение координат точки под курсором;
- увеличение выбранной мышью области;
- масштабирование колесом относительно курсора;
- восстановление начального масштаба;
- оформление в стиле терминальной утилиты `btop`.

## Краткое объяснение проекта

Программа рассматривает каждый пиксель изображения как комплексное число.
После этого для точки много раз вычисляется формула:

```text
z(n + 1) = z(n)² + c
```

Если модуль `z` становится больше двух, последовательность считается
убегающей. Количество итераций до выхода определяет цвет пикселя. Если точка
не вышла за границу после `240` итераций, она рисуется почти чёрной и считается
принадлежащей множеству.

## Что такое комплексное число

Комплексное число состоит из действительной и мнимой частей:

```text
z = a + bi
```

В программе отдельный тип комплексного числа не создаётся. Число хранится в
двух переменных:

```c
double zr;  // действительная часть z
double zi;  // мнимая часть z
```

Константа `c` также хранится двумя числами: `cr` и `ci`.

Квадрат комплексного числа вычисляется по правилу:

```text
(a + bi)² = (a² - b²) + 2abi
```

Поэтому одна итерация в функции `escape_iterations` записана так:

```c
double next_real = zr * zr - zi * zi + cr;
zi = 2.0 * zr * zi + ci;
zr = next_real;
```

Сначала действительная часть сохраняется в `next_real`, потому что для
вычисления новой мнимой части ещё нужно старое значение `zr`.

## Разница между Мандельбротом и Жюлиа

Оба множества используют одну формулу, но начальные значения отличаются.

### Множество Мандельброта

Для каждого пикселя:

```text
z = 0
c = координата пикселя
```

То есть программа проверяет разные значения `c`.

### Множество Жюлиа

Для каждого пикселя:

```text
z = координата пикселя
c = значение с ползунков
```

Во всём изображении используется одна константа `c`, но начальная точка `z`
разная. Поэтому изменение ползунков полностью меняет форму множества Жюлиа.

Выбор между этими вариантами выполняется в `render_fractal`:

```c
double zr = julia ? point_r : 0.0;
double zi = julia ? point_i : 0.0;
double cr = julia ? fixed_cr : point_r;
double ci = julia ? fixed_ci : point_i;
```

`? :` — это сокращённая запись обычного `if`.

## Как пиксель превращается в комплексное число

У изображения одна система координат, а у комплексной плоскости другая.

- координата пикселя `x` меняется от `0` до ширины окна;
- координата пикселя `y` меняется от `0` до высоты окна;
- действительная координата меняется от `view.left` до `view.right`;
- мнимая координата меняется от `view.top` до `view.bottom`.

Функция `map_value` линейно переводит значение из одного диапазона в другой:

```text
результат = начало_нового_диапазона
          + доля_старого_диапазона × длина_нового_диапазона
```

Ось `Y` на экране направлена вниз, а мнимая ось математической плоскости —
вверх. Поэтому экранные координаты переводятся от `top` к `bottom`.

## Главный цикл отрисовки

Отрисовка выполняется функцией `render_fractal`.

Она делает следующее:

1. Получает размер области рисования.
2. Создаёт изображение Cairo нужного размера.
3. Проходит двумя циклами по всем пикселям.
4. Переводит пиксель в комплексные координаты.
5. Выбирает начальные значения для Мандельброта или Жюлиа.
6. Вызывает `escape_iterations`.
7. Получает цвет через `color_for`.
8. Записывает цвет в память изображения.
9. Просит GTK показать готовое изображение.

Упрощённая схема:

```text
каждая строка изображения
└── каждый пиксель строки
    ├── получить комплексную координату
    ├── вычислить количество итераций
    └── записать цвет
```

## Почему проверяется радиус 2

Квадрат модуля комплексного числа равен:

```text
|z|² = Re(z)² + Im(z)²
```

Если `|z| > 2`, последовательность уже не вернётся назад и будет уходить в
бесконечность. Чтобы не вычислять квадратный корень, программа сравнивает
квадрат модуля с четырьмя:

```c
zr * zr + zi * zi <= 4.0
```

Это быстрее и даёт тот же результат.

## Как получается цвет

Функция `color_for` получает количество итераций. Для красного, зелёного и
синего каналов используются косинусы со сдвигом фазы. Поэтому цвет плавно
переходит между синим, фиолетовым, розовым, оранжевым и другими оттенками.

```c
red   = 128 + 127 * cos(phase);
green = 128 + 127 * cos(phase + 2.094);
blue  = 128 + 127 * cos(phase + 4.188);
```

Число `2.094` приблизительно равно одной трети полного оборота `2π`. Благодаря
сдвигу каналы достигают максимума в разное время и создают многоцветную
палитру. Точки, дошедшие до максимального количества итераций, рисуются почти
чёрными.

## Масштабирование выделенной области

При нажатии левой кнопки запоминается начальная точка. Во время движения мыши
обновляется конечная точка и рисуется пунктирный контур с угловыми метками.

После отпускания кнопки:

1. Координаты прямоугольника переводятся в комплексные числа.
2. Они становятся новыми границами `left`, `right`, `bottom` и `top`.
3. Границы корректируются под пропорции области рисования.
4. Фрактал строится заново.

Коррекция пропорций нужна, чтобы изображение не растягивалось по горизонтали
или вертикали. Если выделенная область слишком широкая, увеличивается её
высота. Если слишком высокая — увеличивается ширина.

## Масштабирование колесом

Функция `scroll_cb` сначала находит комплексную координату под курсором. Затем
каждая граница приближается к этой точке или отдаляется от неё:

```c
new_left = center + (old_left - center) * factor;
```

При коэффициенте меньше единицы происходит увеличение, а при коэффициенте
больше единицы — уменьшение. Поэтому точка под курсором остаётся на месте.

## Изменение константы Жюлиа

Ползунки GTK испускают сигнал `value-changed`. Он связан с функцией
`scale_changed_cb`. Обработчик запускает таймер на `55` миллисекунд.

Если пользователь продолжает двигать ползунок, старый таймер удаляется и
создаётся новый. Благодаря этому программа не пытается построить десятки
тяжёлых изображений одновременно. После остановки ползунка вызывается
`render_fractal` с новым значением `c`.

## Основные структуры данных

### `Viewport`

Хранит границы видимой комплексной плоскости:

```c
typedef struct {
    double left, right, bottom, top;
} Viewport;
```

### `App`

Хранит состояние всей программы:

- указатели на элементы GTK;
- готовое изображение Cairo;
- текущие границы комплексной плоскости;
- размеры изображения;
- состояние выделения мышью;
- координаты курсора;
- номер таймера перерисовки.

Структура передаётся в обработчики через `user_data`. Благодаря этому не нужно
создавать множество глобальных переменных.

## Как GTK связывает действия с функциями

GTK работает через события, которые называются сигналами. Например:

```c
g_signal_connect(draw_button, "clicked",
                 G_CALLBACK(redraw_clicked_cb), app);
```

Эта строка означает: когда нажата кнопка `draw_button`, вызвать функцию
`redraw_clicked_cb` и передать ей состояние `app`.

Таким же способом подключены:

- изменение списка;
- движение ползунков;
- движение мыши;
- выделение области;
- вращение колеса;
- нажатия кнопок.

## Зачем нужны GTK и Cairo

GTK отвечает за окно, кнопки, список, ползунки и события мыши. Cairo отвечает
за растровое изображение и рисование контура выделения. Сама формула фрактала
не зависит от GTK или Cairo и написана на обычном C.

Цвет каждого пикселя записывается непосредственно в память поверхности Cairo:

```c
row[px] = color_for(escape_iterations(zr, zi, cr, ci));
```

Формат `CAIRO_FORMAT_RGB24` хранит красный, зелёный и синий каналы пикселя.

## Память программы

При каждой полной перерисовке старая поверхность Cairo удаляется:

```c
cairo_surface_destroy(app->surface);
```

Затем создаётся поверхность нового размера. При завершении приложения также
освобождаются поверхность, объект GTK-приложения и структура `App`.

## Самопроверка

При запуске с параметром `--self-test` окно не открывается. Программа проверяет
две известные точки:

- `c = 0` не должна покинуть множество Мандельброта;
- `c = 2 + 2i` должна выйти за радиус очень быстро.

Это проверяет основную математическую функцию без графического интерфейса.

> Интерфейс сделан на GTK 4, а изображение выводится через Cairo. Каждый
> пиксель переводится в точку комплексной плоскости. Для неё до 240 раз
> вычисляется формула z следующего равно z в квадрате плюс c. Если модуль z
> становится больше двух, я запоминаю количество итераций и по нему выбираю

4. Масштабирование колесом.
5. Переключение на Жюлиа.
6. Изменение действительной и мнимой частей `c`.

## Возможные вопросы преподавателя

### Почему граница равна двум?

Если модуль `z` стал больше двух, дальнейшие значения последовательности будут
расти и точка не принадлежит множеству. В коде сравнивается квадрат модуля с
четырьмя, чтобы не вычислять квадратный корень.

### Почему используется ограничение числа итераций?

Нельзя выполнять бесконечный цикл. Чем больше предел, тем точнее граница
фрактала, но тем дольше строится изображение. В проекте выбран компромисс —
240 итераций.

### Почему фрактал состоит из пикселей?

Экран является дискретным. Для каждого пикселя выбирается одна точка
комплексной плоскости и вычисляется её цвет.

### Чем Жюлиа отличается от Мандельброта в коде?

Только начальными значениями `z` и `c`. Формула и функция итераций общие.

### Почему интерфейс не зависает при движении ползунка?

Перерисовка запускается через короткий таймер. Пока ползунок продолжает
двигаться, таймер перезапускается. Тяжёлое вычисление начинается после короткой
паузы.

### Зачем сохранять пропорции при выделении?

Без этого один шаг по действительной оси имел бы другой визуальный размер, чем
такой же шаг по мнимой оси. Фрактал выглядел бы растянутым.

### Почему выбран язык C?

C позволяет явно реализовать математический алгоритм и напрямую работать с
памятью изображения. GTK и Cairo предоставляют только интерфейс и вывод
графики.

### Что можно улучшить дальше?

- считать строки изображения в нескольких потоках;
- добавить сохранение результата в PNG;
- добавить выбор количества итераций;
- добавить другие формулы фракталов;
- хранить историю масштабирования.
